# MarginMark — Nonprod Test Plan & Release Gates

Goal: every number a seller sees is correct, every page we read is read correctly, and payments/upgrades behave, **before** a real user installs it.

Put this file at `qa/TEST_PLAN.md` and `golden-cases.json` at `qa/golden-cases.json`.

## What can go wrong (and which layer catches it)

| Risk | Example | Caught by |
|---|---|---|
| Math wrong | commission double-counted, break-even off | L1 golden + property tests |
| Page read wrong | picks up compare-at price, misses variants | L2 fixtures, L3 E2E, L7 manual |
| Saved data lost/corrupted | upgrade wipes COGS | L4 migration |
| Statement import wrong | refunds counted twice, wrong column | L5 reconciliation |
| Payments/Pro wrong | paid user stays Free, cancel keeps Pro | L6 Stripe test mode |
| Prod build wrong | localhost left in, dev API URL shipped | L8 build check |
| Breaks after launch | TikTok changes its HTML | L10 monitoring + canary |

## L1 — Math (automated)

### 1a. Golden tests (independent answer key)
`qa/golden-cases.json` was generated by a **separate** implementation of the spec formulas, not from our TS code. That way the tests aren't checking the code against itself.

Cursor task: create `src/lib/golden.test.ts` that:
- Loads every case, maps `input` → `computeProfit` / `maxSafeCommission` / `maxCpa` / `breakEvenRoas` etc.
- Compares every `expected` field. Tolerance: money ±$0.01, percent ±0.05, ratios ±0.01.
- `null` expected means "not possible" → code must return `null` (and UI must show "Not profitable at any price with these costs"), never `Infinity`, `NaN`, or a negative price.
- **Rule:** if code and golden disagree, investigate and fix whichever is wrong. Never just overwrite the expected value to make the test pass.

Cases cover: spec examples A & B, 0/50/100% creator share, seller vs buyer shipping, legacy 6% + 2.9% + $0.30 fees, ads, sales tax, sample amortization (incl. 0 units sold), odd cents, $1,000 item, zero COGS, COGS above price, unprofitable at any price, target unreachable, price = 0 while the editor loads.

### 1b. Property tests (catch bugs no one thought of)
Add `fast-check` (`npm i -D fast-check`). Generate 1,000 random valid inputs per rule and assert:
- At `price = breakEvenPrice` → blended net ≈ $0 (±0.01).
- At `commission = maxCommissionBreakEvenPct` → creator net ≈ $0.
- At `commission = maxCommissionTargetPct` → creator margin ≈ target.
- `roas × maxCpa ≈ price` whenever maxCpa > 0.
- Raising commission, COGS, fees, ads or refund % never **increases** net. Raising price never **decreases** net.
- Net direct ≥ net blended ≥ net creator.
- No output is ever `NaN` or `Infinity`.

### 1c. Display
- Test `formatUsd`/`formatPct` on negatives (`-$1.10`, not `$-1.10`), 0, and large values (`$12,345.67`).
- Status color and text always agree (red is always paired with "Loss"/"Below break-even").

## L2 — Reading TikTok pages (fixtures)

Scraping is the most fragile part. Test against **real saved pages**, not hand-made mocks.

### How to capture a fixture (BossMan, on the test shop)
1. Open the page in Seller Center and wait until it has fully loaded.
2. DevTools → Elements → right-click `<html>` → Copy → **Copy outerHTML** → paste into `test-fixtures/<name>.html`.
3. Scrub personal data (shop name, email, address, order IDs). Keep structure, labels, prices.
4. Add a matching `test-fixtures/<name>.expected.json` with what a human sees on screen (title, price, units sold, SKU IDs).

### Fixture list (minimum)
| Fixture | Why |
|---|---|
| Product edit — single SKU | base case |
| Product edit — **multiple variants** (sizes/colors, different prices) | most likely silent bug: wrong variant's price |
| Product create (empty form) | must show "enter price", not $0 profit |
| Product with **sale/discount price** set | must use the price the buyer pays |
| Manage products — page 1, and page 2 (pagination) | bulk import |
| Manage products — search/filter applied | table still parsed |
| Manage products — a product with 0 sales | "—" not 0 |
| Prices with thousands separator (`$1,234.50`) | parseMoney |
| Statement export CSV + XLSX | L5 |
| Affiliate Center commission page | enables the affiliate chip later |

Cursor task: one parser test per fixture comparing to `.expected.json`. Every time a real-world scrape bug is found, save that page as a new fixture **before** fixing it.

**Failure rule:** if a required field can't be read, the overlay shows the manual-entry prompt. It must **never** show a profit computed from a missing or $0 price.

## L3 — End-to-end in a real browser (Playwright, automated)

Cursor task: `e2e/` suite using `@playwright/test` with Chromium from `/opt/pw-browsers` or local install:
- `chromium.launchPersistentContext(tmpProfile, { args: ['--disable-extensions-except=dist', '--load-extension=dist'] })`
- Serve `test-fixtures/` on `http://127.0.0.1:8765` (already allowed in the dev manifest).

Scenarios:
1. Fresh install → onboarding shows → pick preset → defaults saved.
2. Product fixture → overlay appears → headline matches the golden value for the same inputs.
3. Type a new price into the fixture's price field → overlay updates within 1 s; below break-even → red banner.
4. Edit COGS in overlay → reload page → value persists → dashboard row shows same net.
5. Manage products fixture → import → row count matches fixture → "Missing cost" filter correct.
6. Free user: 11th SKU is blocked with the upgrade message; Pro-only cards show upsell.
7. Pro user (mock `/auth/me` → `is_pro: true`): max commission, ads card, what-if, export work.
8. Collapse/expand/dismiss persists across navigation.
9. Backend offline → extension still works on cached tier, no crash, clear message.
10. Overlay never covers the page's Save/Submit button (check bounding boxes).

## L4 — Saved data & upgrades

Automated:
- v1 settings object → load → v2 with new fields defaulted, old values untouched (incl. old payment fee values).
- SKU records missing new fields (`costSource`, samples) load safely.
- Corrupted storage (bad JSON, wrong types) → falls back to defaults, doesn't crash, doesn't wipe the SKU list.

Manual in real Chrome (do once per release):
1. Load **v0.1.6** unpacked. Set custom fees and COGS on 3 products.
2. Replace the folder with **v0.2.0** build → chrome://extensions → reload.
3. Confirm all 3 COGS and settings are still there and numbers make sense.

## L5 — Statement import accuracy

1. Export a real settlement/order statement from the test shop (CSV and XLSX if both exist).
2. Pick 20 orders. Hand-calculate each in a spreadsheet: what was the referral fee, affiliate commission, refund, shipping, net payout.
3. Import into the extension. Per-SKU fee rates and net must match the spreadsheet: **money ±$0.01 per order, totals ±0.5%**.
4. Totals from import must equal the statement's own payout total.

Edge files (automated tests): empty file, header only, wrong file type, 50,000 rows (must finish < 5 s, no freeze), refunds as negative rows, commas/quotes in product names, UTF-8 BOM, same order split across rows, SKU not in dashboard (creates or reports it, doesn't drop silently).

Confirm in DevTools → Network that **no request** is sent during import.

## L6 — Payments & Pro (nonprod backend + Stripe **test mode**)

Setup: nonprod backend (`fly.lle.toml`) with Stripe **test** keys; `stripe listen --forward-to <nonprod>/stripe/webhook`.

| Scenario | Card / action | Expected |
|---|---|---|
| Monthly upgrade | `4242 4242 4242 4242` | Pro unlocks after reopening popup (≤ 1 min) |
| Yearly upgrade | `4242…` | Pro, yearly price in Stripe |
| Declined | `4000 0000 0000 0002` | stays Free, clear error |
| 3-D Secure | `4000 0025 0000 3155` | completes after auth |
| Renewal fails | `stripe trigger invoice.payment_failed` | defined behavior (grace or downgrade), documented |
| Cancel | Customer Portal → cancel | Pro until period end, then Free |
| Duplicate webhook | resend same event | no double subscription |
| Server-side limit | Free user syncs 11th SKU via API | `402` |
| Log out / log in other account | | tier follows the account, not the browser |

**7-day trial:** it can be enabled for this product only by passing `subscription_data.trial_period_days=7` in the Checkout Session **only when `service == "tiktok-seller-tool"`**. That leaves the other services unchanged. Test: trial start → Pro, trial end with `4000 0000 0000 0341` → downgrade.

## L8 — Production build verification

1. Run `.\scripts\build-prod.ps1` (never `npm run build` for the store zip).
2. Automated check (Cursor: `scripts/verify-prod.mjs`, run inside `build-prod.ps1`) fails the build if `dist/manifest.json`:
   - contains `localhost` or `127.0.0.1`
   - has a version not greater than the last published version
   - has permissions beyond `storage`, `alarms`, and `scripting`, or a permission with no `chrome.<api>` use
   - or the bundle contains the nonprod API URL, Stripe test keys (`pk_test_`), or `VITE_SHOW_CREATOR_DEMO`
3. Unzip the store zip into a **fresh Chrome profile**, load unpacked, repeat L7 checks 1, 2, 5 against the **prod** API.
4. Extension ID: add the CWS public `key` to the dev manifest so dev and store builds share one ID. Otherwise OAuth redirect URLs (`https://<id>.chromiumapp.org/`) differ and sign-in breaks only in prod.

## L9 — Staged release

1. Chrome Web Store → visibility **Private / Trusted testers** → invite yourself + 3–10 real sellers.
2. Each tester compares 3 products against their last payout. Collect: wrong numbers, pages that didn't load, confusion.
3. 7 days with no open P1 (wrong number / crash / payment) → publish public.
4. **Rollback reality:** the store can't instantly revert; a fix goes through review again. So add a **remote kill switch**: backend `GET /config` → `{ overlayEnabled, statementImportEnabled, minSupportedVersion }`, cached 1 h. Test that flipping it off hides the feature without a new release.

## L10 — After launch

- Error reporting (e.g. Sentry browser SDK) on content script, popup, service worker; scrub personal data.
- Anonymous counter: "scrape failed on page type X" (opt-in, disclosed in privacy policy). Spike = TikTok changed its HTML.
- Weekly canary: open the saved fixture page types on the live test shop, compare to expected; re-save fixtures that changed.
- Support ticket flow tested end to end (ticket reaches you).

## Bug severity
- **P1:** wrong profit number, data loss, paid user not Pro, crash on Seller Center → blocks release.
- **P2:** feature broken with a workaround → fix before public.
- **P3:** cosmetic → backlog.
